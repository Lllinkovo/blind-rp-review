# Blind RP Review · RP 盲审

**让研究计划中的每一个关键判断，都经得起追问。**

Blind RP Review 是一个面向博士研究计划的多角色盲审 skill。它将研究问题、文献贡献、引文依据和研究方法分别交给专项角色审查，再由裁决角色核对证据、处理分歧，形成附有具体位置和修改顺序的审查报告。

[English](README_EN.md) · [使用方法](#使用) · [示例与验证](#示例与验证)

## 为什么做它

和 AI 一起修改研究计划时，对话里会逐渐积累作者的解释、已经接受的判断和此前的修改理由。继续在同一段对话里审查，模型可能沿用这些信息，而读到最终稿的评审未必能从正文中找到相同的依据。

Blind RP Review 将既有评价与写作上下文移出专项审查输入，要求审查者从指定版本重新建立判断：研究究竟在问什么？文献能否支持这个缺口？方法能否回答问题？如果受到最强质疑，方案里有什么证据可以回应？

## 核心优势

### 1. 从研究计划本身重新判断

完整模式使用不继承写作对话的新上下文。已有评语、预期答案和作者希望得到的结论保持隐藏，直到审查结果冻结后再进入对照环节。

### 2. 把四类问题分别查清楚

研究问题、文献贡献、主张与来源、方法与推论各有独立的审查任务。每个角色先完成自己的报告，裁决角色随后处理重叠与冲突。读者可以看清一个问题出在哪里、影响了哪一段推理。

### 3. 严重判断必须经得起反驳

每个阻断性问题都要说明具体证据、核心影响，以及最强的辩护或替代方案为什么仍不足以解决它。可行的替代方案能够降低问题等级；暂时读不到的文献则按未知状态记录。

### 4. 每次结论对应一个明确版本

研究计划与各阶段报告都有文件校验记录。裁决前重新核对内容，发现文件变化时使相关后续结果失效，并要求对新版本重新审查。这样可以核对一条结论究竟依据了哪份材料。

### 5. 把审查发现转成修改顺序

每项重要发现附带证据位置、失败条件、最强反驳和解决条件。最终给出最多三项优先修改，说明改动需要达到什么标准，便于下一轮复审逐项核对。

## 适合什么时候使用

- 完成一轮研究计划后，检查问题、贡献与方法之间是否连贯。
- 经历多轮 AI 修改后，重新审查最终正文能否支撑已有判断。
- 收到导师或评审意见后，先完成隐藏这些意见的审查，再逐项比较。
- 修改关键设计后，复核原有问题是否解决，以及是否引入新问题。

## 工作方式

```text
研究计划 → S0 版本与范围记录
              ├─ S1 研究对象、问题、学科位置
              ├─ S2 文献、缺口、贡献
              ├─ S3 主张与来源
              └─ S4 方法、推论、进入现场的条件
                       ↓ 报告冻结与文件校验
                   S5 分歧裁决
                       ↓
              结论 + 证据位置 + 修改优先级
                       ↓ 可选
                 与人工意见比较
```

- 每个审查角色有自己的输入清单。
- 裁决前校验研究计划、S0 和四份报告的文件内容。
- 不通过投票或平均分消除严重问题。
- 保留最强反驳；可行的替代方案可以改变问题等级。
- 人工意见与预期答案在结论冻结后才交给评估者。

这里的“盲”指隐藏既有评价与上下文。作者身份不会自动匿名化。不同角色可能使用同一模型，仍可能共享偏差；输入清单的隔离方式会在报告中说明。

## 使用

仓库：[Lllinkovo/blind-rp-review](https://github.com/Lllinkovo/blind-rp-review)。将本仓库克隆到宿主的 skill 目录，保留本地目录名 `stress-test-phd-rp`，然后在新会话中确认技能可用。

```text
git clone https://github.com/Lllinkovo/blind-rp-review.git stress-test-phd-rp
```

已有同名技能时，请先比较两个版本，再决定使用哪一份。

```text
用 $stress-test-phd-rp 盲审这份博士研究计划。
只读审查；各角色不继承本次对话。
先给出最强拒稿理由及其证据，再给出修改顺序。
```

已有人工意见时：

```text
先用 $stress-test-phd-rp 审查 proposal.md。
人工意见另行保管，结论冻结后再比较。
```

**运行条件：** 能读取本地文件的 Agent；Python 3.10 或更新版本用于校验脚本；完整隔离模式需要可创建无继承上下文的子角色。PDF/Word 解析由宿主提供。默认最多同时运行两项专项审查。

可调用的技能名是 `stress-test-phd-rp`，适用材料为博士研究计划与概念稿。审查深度按材料类型和篇幅调整。

不支持新上下文的宿主可以顺序审查，但报告必须标记 `REDUCED_ISOLATION_SINGLE_CONTEXT`。本仓库提供指令、角色规范和文件校验脚本，角色调度由宿主完成。

## 输出

- `BLOCK`：核心失败经最强反驳检验后仍成立。
- `MAJOR REVISION`：存在重要问题，且有保留核心研究的修复路径。
- `PASS FOR HUMAN REVIEW`：本次范围内未留下严重或重要缺陷。

每项重要发现包括证据位置、失败条件、影响、最强反驳、剩余问题、发现置信度、严重程度置信度和清除条件。文件哈希只校验内容一致性。
